# ADR-0009 — Key Management

**Status:** Proposed — Decision Pending Review  
**Date:** 2026-10-02  
**Related ADRs:** ADR-0007, ADR-0008

## Context
Define generation, protection, lifecycle, rotation, revocation, recovery/migration, and platform abstraction for long-lived identity keys and session keys.

## Candidate approaches
### Android Keystore
Evaluate platform-backed protection for long-term identity material, including API-level support, hardware-backed/StrongBox availability, attestation requirements, and testability.

### Maintained cryptographic library abstraction
Evaluate use of a maintained library for primitives while retaining platform protection for long-lived secrets where appropriate.

### External native implementation
Evaluate a mature native crypto implementation behind a narrow boundary, including JNI/native integration, memory handling, key extraction risks, maintenance, and provenance.

## Non-negotiable constraints
- private keys do not cross public module boundaries
- UI does not access private keys
- storage does not become a private-key repository
- long-lived secrets require explicit lifecycle/recovery design
- cryptographic choices remain governed by ADR-0008

## Decision
Pending review. No concrete library or hybrid design is approved by this draft.

## Required acceptance evidence
- selected key-storage model
- supported Android API range
- threat assumptions
- failure/recovery behavior
- testability strategy
- migration impact
