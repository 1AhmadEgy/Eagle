# ADR-0012 — Direct P2P Transport Architecture

**Status:** Proposed — Decision Pending Review
**Date:** 2026-10-05

## Decision scope

Define the transport boundary for Eagle under the project-wide P2P-only constraint.

## Security decision candidate

- Primary data transport: direct QUIC v1.
- Candidate implementation: rust-libp2p QUIC, isolated behind the transport boundary.
- Transport encryption: TLS 1.3 provided by QUIC.
- Peer authentication: authenticated peer identity bound to the transport connection.
- NAT traversal: direct hole punching where supported.
- Relay/TURN/content forwarding: prohibited for application data.
- Rendezvous/discovery: optional and non-authoritative; discovery data must never become a trust root.
- Direct-connect failure: remain offline/unavailable; do not fall back to server-mediated application transport.

## Threat controls

| Threat | Required control |
|---|---|
| MITM | cryptographic peer identity authentication + application identity binding |
| Endpoint spoofing | authenticated peer identity + verified device membership |
| Replay | transport/application freshness and session replay protection |
| Downgrade | authenticated version policy; unsupported versions fail closed |
| Malicious peer | parser bounds, authorization state machine, resource limits |
| NAT abuse | rate limits, connection caps, address validation |
| Relay privacy violation | relay capability disabled for application content |
| Metadata leakage | minimize discovery data; do not expose identifiers unnecessarily |
| DoS | bounded handshake/work, backoff, connection quotas |
| Stale/revoked peer | authorization re-check before privileged operations |

## Non-goals

This ADR does not choose the message cryptographic protocol, key hierarchy, serialization, local storage, or platform secure-storage API.

## Acceptance evidence

Approval requires:
1. platform build proof for Android, Desktop, and iOS target plan;
2. direct-connect and NAT behavior tests;
3. identity-to-transport binding tests;
4. malicious-peer and resource-exhaustion tests;
5. explicit evidence that application content cannot use relay paths;
6. privacy review of discovery metadata;
7. independent security review of the final transport integration.
