# ADR-0010 — Serialization

**Status:** Proposed — Decision Pending Review  
**Date:** 2026-10-02  
**Related ADRs:** ADR-0007, ADR-0008, ADR-0009

## Context
Define serialization for encrypted envelopes, packet framing, persisted encrypted records, and protocol metadata. Requirements include compact size, predictable parsing, versioning, schema evolution, Kotlin/Android support, and auditability.

## Candidate formats
- Protocol Buffers: evaluate schema-first evolution, generated code, tooling, size, build complexity, and compatibility.
- CBOR (RFC 8949): evaluate compact encoding, IETF ecosystem alignment, schema/versioning, and Kotlin support.
- MessagePack: evaluate size/performance and compatibility with project governance.
- FlatBuffers: consider only if zero-copy access is demonstrated to be needed.
- Custom binary: exceptional-risk path because parsing, evolution, and compatibility become project-owned responsibilities.

## Decision criteria
Wire size; parsing performance; versioning/evolution; schema validation; Kotlin/Android support; interoperability; auditability; future standards compatibility.

## Decision
Pending review. No serialization format is approved by this draft.
