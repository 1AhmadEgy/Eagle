# ADR-0010 — Serialization

**Status:** Proposed — Decision Pending Review  
**Date:** 2026-10-02  
**Related ADRs:** ADR-0007, ADR-0008, ADR-0009

## Context
Eagle needs serialization for encrypted message envelopes, packet framing, persisted encrypted records/session state, and future protocol metadata. Requirements include compact representation, predictable parsing, versioning, schema evolution, Kotlin interoperability, and auditability.

## Options to investigate
### Protocol Buffers
Evaluate schema-first evolution, generated code, tooling maturity, binary size, build complexity, and compatibility guarantees.

### CBOR (RFC 8949)
Evaluate compact binary encoding, IETF ecosystem alignment, schema/versioning strategy, Kotlin libraries, and fit for constrained transports.

### MessagePack
Evaluate size/performance and Kotlin integration against the project's schema and governance requirements.

### FlatBuffers
Evaluate only if zero-copy access is a demonstrated requirement.

### Custom binary
Treat custom wire formats as exceptional-risk because parsing, evolution, compatibility, and security become project-owned responsibilities.

## Decision criteria
- wire size
- parsing/serialization performance
- versioning/evolution
- schema validation
- Kotlin/Android support
- interoperability
- auditability
- compatibility with future security standards

## Decision
Pending review. No serialization format is approved by this draft.

## Consequence
PROTO-001 and PROTO-003 remain blocked until the accepted decision is recorded.
