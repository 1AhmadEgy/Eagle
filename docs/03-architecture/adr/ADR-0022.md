# ADR-0022 — Reproducible Statistical Benchmark Harness

Status: Implemented as JVM evaluation harness; device benchmark pending
Date: 2026-10-04

## Decision

Add a deterministic JVM evaluation harness that runs feature-aware Z-score, EWMA, and Median/MAD over one identical synthetic dataset and explicit feature. Include threshold sweeps and deterministic hashes.

The harness reports classification metrics, drift sensitivity, diagnostic timing, and deterministic hashes.

## Rationale

This provides a reproducible comparison surface before adding a heavier ML dependency.

## Important qualification

The three algorithms use different score semantics. A shared numeric threshold is therefore a smoke-test condition only. Threshold sensitivity is reported per algorithm and should be used for primary comparison.

## Android performance

JVM timing does not substitute for Android/device measurements. AndroidX Microbenchmark 1.5.0 is the approved candidate for later device-level timing/allocation verification after the security code resides in a benchmarkable library module.

## Non-goals

The harness does not choose production thresholds, make policy decisions, train ML models, or represent production telemetry.
