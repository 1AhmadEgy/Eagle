# ADR-0008 — Cryptographic Protocol

**Status:** Decision package completed — production implementation approval pending evidence  
**Date:** 2026-10-02  
**Related ADR:** ADR-0007

## Context
Evaluate an E2E protocol for asynchronous and unreliable transports against asynchronous delivery, forward secrecy, post-compromise security, device lifecycle, future multi-device/group requirements, mobile constraints, auditability, and maintenance.

## Candidate families
- Signal-family protocols: evaluate async messaging, ratcheting, runtime/library support, maintenance, licensing, and multi-device model.
- Noise framework: evaluate authenticated handshakes plus the additional session/message-ratcheting layer Eagle would need.
- MLS (RFC 9420): evaluate group messaging, Android integration, 1:1 overhead, asynchronous delivery, and implementation maturity.
- Custom protocol: exceptional-risk path requiring strong justification and independent review.

## Decision criteria
Async messaging; forward secrecy; post-compromise security; mobile suitability; multi-device model; group roadmap; maintenance; supply-chain provenance; auditability.

## Decision
Pending review. No protocol is approved by this draft.

## Constraint
Do not implement custom cryptographic protocol logic solely from this planning draft.
    
## Security-specialty closure

The security specialty baseline selects the Signal Protocol family as the one-to-one protocol target, with PQXDH for asynchronous session establishment and a Signal-defined post-PQXDH ratchet target. The current research baseline is Triple Ratchet (Double Ratchet + SPQR/SCKA) for strongest ongoing post-quantum security, with Double Ratchet retained only where an explicit interoperability requirement prevents the stronger profile. No custom ratchet or primitive is permitted.

The implementation library is deliberately not forced by this ADR. libsignal is reference/conformance material until Eagle completes support, API, license, platform, provenance, and exact-version review. vodozemac remains a candidate for ratchet-compatible research but is not treated as a drop-in PQXDH implementation.

Production approval requires conformance vectors, interoperability evidence, adversarial testing, exact dependency provenance, protocol-version negotiation tests, and independent cryptographic review. The chosen ratchet profile must be pinned to a published specification/version and must not be reconstructed by composing unrelated primitives.
