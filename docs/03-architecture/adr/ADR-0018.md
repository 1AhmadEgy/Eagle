# ADR-0018 — Deterministic Session State Machine

Status: Implemented in Kotlin; build verification pending
Date: 2026-10-04

## Decision

Introduce a synchronized session state machine with explicit states:
NEW, AUTHENTICATING, ESTABLISHED, REKEYING, CLOSED.

Only documented transitions are accepted. CLOSED is terminal.

## Rationale

Session lifecycle correctness must be deterministic and must not depend on an AI/ML score. Explicit states also give replay protection and telemetry a stable context boundary.

## Security constraints

Transition to ESTABLISHED is not proof of authentication. The eventual session coordinator must complete cryptographic authentication, transcript/key binding, and authorization checks before requesting that transition.

Replay state is session-scoped and must be discarded when its owning session closes.
