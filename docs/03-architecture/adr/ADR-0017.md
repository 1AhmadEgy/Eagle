# ADR-0017 — Per-session Replay Guard

**Status:** Implemented in Kotlin; build verification pending  
**Date:** 2026-10-04

## Context

Eagle needs deterministic replay detection independent of AI/ML. The verified Android/JVM runtime supports a small local implementation and JUnit tests.

## Decision

Implement a synchronized sliding-window sequence guard in:

- `app/src/main/java/com/eagle/app/security/ReplayGuard.kt`
- `app/src/test/java/com/eagle/app/security/ReplayGuardTest.kt`

The window size is configurable from 1 to 64. Sequence numbers are non-negative Long values. The guard accepts new sequence numbers and bounded out-of-order delivery, rejects duplicates and values older than the window, and rejects negative sequence values.

## Trust boundary

The caller must verify message authenticity and bind the message to a session **before** calling the guard. Unauthenticated input must never advance replay state.

Each guard instance belongs to exactly one authenticated session. It must not be shared between peers or sessions, and it must not be reset by untrusted input.

## Explicit non-goals

This decision does not implement authentication, cryptographic nonce generation, timestamp freshness, key management, session establishment, or distributed replay state. It does not allow ML to override protocol decisions.

Sequence wraparound is not supported; establish a new authenticated session before exhausting the non-negative Long range.

## Verification status

JUnit tests were added. Build/test status remains pending because the actual Gradle verification gate has not been run successfully in the current environment.

## Follow-up

Integrate the guard only after the protocol authentication/session layer exists. Next define the session state machine and the SecurityEvent contract so replay decisions can produce privacy-minimized, versioned telemetry.
