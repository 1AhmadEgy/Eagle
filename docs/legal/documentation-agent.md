# Eagle Continuous Documentation Agent

## Purpose

This document defines the permanent documentation/provenance process for Eagle.

The documentation process records the evolution of the project without granting third parties any additional intellectual-property rights.

## Ownership policy

- Project ownership intent: **PRIVATE / ALL RIGHTS RESERVED**
- Copyright holder: **UNCONFIRMED** until the owner supplies the exact legal name to use in project notices.
- Open-source license: **NOT GRANTED**
- This document is project governance documentation, not legal advice.

The absence of an open-source license must not be interpreted by contributors or automation as permission to reuse, redistribute, sublicense, or create derivative works.

## What is recorded

The continuous record may include:

- Git commit SHA and timestamp
- branch and release references
- authors and committers as exposed by GitHub/Git
- pull requests and review evidence
- changed files and architectural impact
- CI and Test Lab evidence
- dependency and third-party provenance
- AI-assisted development disclosures
- unresolved ownership metadata

## Evidence rules

Only observable repository/GitHub evidence is recorded as confirmed.

Unknown legal facts are explicitly marked **UNCONFIRMED**.

Git history is treated as provenance evidence; it is not described as a substitute for formal copyright registration, notarization, or other jurisdiction-specific legal procedures.

## Change policy

The documentation agent may update only approved documentation paths and must never alter product behavior or weaken security controls.

All automated documentation changes should remain reviewable through a pull request. No automated documentation agent may merge its own pull request.

## AI-assisted development

AI tools are documented as development assistants. The project records the human-controlled engineering process, review, testing, and resulting repository changes. The agent must not make a legal determination about copyrightability or authorship.

## Retention

Do not delete historical provenance records merely to make the repository look cleaner. Corrections should be additive and explain what changed.

## Owner action required

The exact legal copyright-holder name is intentionally left unconfirmed until supplied by the project owner. Once supplied, it can be inserted consistently into the ownership records and copyright notices.
