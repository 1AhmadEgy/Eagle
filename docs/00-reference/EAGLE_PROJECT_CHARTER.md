# Eagle Project Charter

## 1. الغرض

بناء منصة مراسلات آمنة ومستقرة وسريعة وقابلة للصيانة عبر Android وiOS وDesktop، مع جعل الأمن جزءًا من التصميم وليس مرحلة لاحقة.

## 2. مبادئ غير قابلة للتفاوض

| المبدأ | القاعدة |
|---|---|
| Security First | لا يُقبل تحسين أداء أو تجربة إذا كسر حدود الأمن. |
| P2P First | الاتصال ونقل الرسائل بين النظراء هو المسار الأساسي. |
| No Third-Party Runtime Dependency | لا تعتمد المنصة وقت التشغيل على خدمة خارجية لتخزين الرسائل أو فرض الثقة. |
| Local Ownership | الهوية والمفاتيح والبيانات الحساسة مملوكة للجهاز/المستخدم. |
| Fail Closed | عند نقص السياق الأمني يُرفض الطلب بدل السماح به. |
| Reuse Mature Components | لا نعيد اختراع مكون ناضج وآمن دون سبب موثق. |
| Evidence Before Claim | لا تُعتبر الميزة مكتملة دون كود واختبار ودليل ومراجعة. |
| Public by Default | الوثائق العامة متاحة للقراءة ما لم تحتوي سرًا أو بيانات حساسة. |
| Small Stable Core | الأمن والمنطق الحساس في نواة مشتركة قدر الإمكان؛ المنصات طبقات تكييف. |

## 3. النطاق

يشمل الهوية والجهاز والثقة، التشفير وإدارة المفاتيح، الجلسات والبروتوكول، P2P، التخزين المحلي والاستعادة والحذف، Android وiOS وDesktop، UI/UX، الاختبارات وFuzzing وConformance، CI/CD، سلسلة التوريد، الإصدارات، والمراقبة والاستجابة للحوادث.

لا يتم اعتماد خوارزمية أو مكتبة محددة من خلال هذا الميثاق؛ الاعتماد يتم عبر البحث والعناية الواجبة وADR.

## 4. تعريف الإنتاج

الإنتاج لا يعني أن التطبيق يبني فقط. يجب أن تكون المتطلبات قابلة للتتبع، والمعمارية والعقود معتمدة، والضوابط الحرجة منفذة ومراجعة، والاختبارات والأدلة والإصدار والاستعادة والتراجع مثبتة.

## 5. حالات المشروع

PROPOSED → REVIEWED → APPROVED → IMPLEMENTED → VERIFIED → RELEASED → OBSERVED

والخلل الجوهري يعيد العنصر إلى REMEDIATION.

## 6. حدود الثقة

كل طبقة أدنى أو peer أو ملف أو مدخل شبكة يُعامل كغير موثوق حتى يثبت العكس. وجود العنصر داخل المستودع لا يمنحه ثقة تلقائية.
