# سجل الفجوات والمخاطر المرجعية

## فجوات حالية

| ID | الفجوة | الأثر | الإجراء المطلوب | الحالة |
|---|---|---|---|---|
| GAP-001 | الأرشيفات التاريخية المشار إليها لم تُستخرج/تفحص بالكامل | لا يمكن إثبات اكتمال المتطلبات أو provenance للمحتوى الخارجي | استرجاع الأرشيفات، hashing، manifest، secret scan، deduplication، classification | Open |
| GAP-002 | لا توجد متطلبات V1 نهائية مثبتة وقابلة للتتبع | يمنع اعتماد تصميم منتج نهائي | استخراج المتطلبات من المصادر الموثوقة ثم اعتماد traceability baseline | Open |
| GAP-003 | Stack الإنتاجي الكامل غير معتمد؛ المتاح حاليًا Android/Gradle stack جزئي ومثبت | يمنع اعتماد بنية متعددة المنصات أو Rust/crypto/mesh | تثبيت حدود Android الحالية ثم اعتماد باقي الـStack وفق المتطلبات | Open |
| GAP-004 | لا يوجد Threat Model تفصيلي مربوط بحدود الثقة الفعلية | مخاطر الهوية/المفاتيح/النقل/التخزين/Mesh غير مكتملة | بناء threat model بعد تثبيت أول trust boundaries والعقود | Open |
| GAP-005 | ملفات CI موجودة، لكن نجاح التشغيل الفعلي لكل commit حرج غير مثبت في سجل الأدلة الحالي | لا يوجد دليل release-grade متكرر | ربط CI/Test Lab runs بالـSHA وحفظ النتائج في provenance | Open |
| GAP-006 | صلاحيات جميع أعضاء الفريق لم تُتحقق حسابيًا | لا يمكن إثبات أقل صلاحية لكل عضو | مراجعة صلاحيات GitHub عند الحاجة وبأدلة حسابية | Open |
| GAP-007 | اختبار التطبيق الحالي SmokeTest tautological ولا يغطي سلوكًا منتجيًا | قد يعطي إشارة إيجابية دون قيمة تحقق حقيقية | استبدال/توسيع الاختبار إلى behavior-level tests مع أول عقدة وظيفية | Open |
| GAP-008 | حالة توافق workflows موثقة تصميميًا، لكن التشغيل المتكامل للمسار privileged AI-repair غير مثبت في هذه المراجعة | خطر اختلاف الوثيقة عن runtime behavior | تنفيذ تحقق آمن على branch موثوق أو تسجيل عدم التحقق بدل الادعاء | Open |

## قاعدة الإغلاق

لا تُغلق الفجوة بمجرد اقتراح حل؛ يجب تسجيل الدليل الذي يثبت تنفيذ الحل والتحقق منه.

## أولوية الأمن

الفجوات التي تمس الأسرار أو الصلاحيات أو المصادقة أو سلامة سلسلة البناء أو إدارة المفاتيح تُعامل كحواجز قبل الإنتاج، وليس كتحسينات اختيارية.
