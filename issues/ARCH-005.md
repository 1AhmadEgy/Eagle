# ARCH-005 — ADR Framework

**Module:** documentation  
**Phase:** foundation  
**Priority:** critical  
**Type:** docs  
**Status:** Proposed

## Purpose
Establish a durable Architecture Decision Record process aligned with the project's existing decision-record convention.

## ADR lifecycle
1. Proposed
2. Architecture review
3. Security review when applicable
4. Compatibility review against existing ADRs
5. Team / project-owner approval
6. Accepted
7. Implementation / verification through linked Issues
8. Deprecated / Superseded when necessary

## Required ADR fields
Status, Date, Deciders, Context, Decision, Consequences, Alternatives, Relationship to existing ADRs, Approval evidence, Linked Issues.

## Separation rule
ADR = decision. Issue = implementation, verification, migration, or follow-up.

## Acceptance criteria
- [ ] ADR template exists
- [ ] ADR index exists
- [ ] process is documented
- [ ] numbering conflicts are explicitly reconciled
- [ ] accepted ADRs link to implementation evidence
- [ ] no sensitive material is stored in ADRs

## Dependencies
Requires: ARCH-001, ADR-0007 acceptance.
